Анастасия 4.11 — обновление диалога и управления
УСТАНОВКА ОБНОВЛЕНИЯ:
1. Остановите программу Ctrl+C и сделайте копию старой папки.
2. Скопируйте все файлы .py и start.cmd из этого архива в рабочую папку с заменой.
3. НЕ заменяйте .env, data и knowledge.json. Они содержат ваши настройки и историю.
4. Запустите start.cmd.
5. Со своего аккаунта напишите «ты тут?»; затем /диалог_тест и тестовый вопрос.
Команды: «покажи заявки», «останови приглашения», /приглашения (также /приглашение), /конец_теста.
Директора исключены из приглашений. Для теста с Настей используйте /диалог_тест.
Первый клиентский ответ содержит короткое уведомление об ИИ, без отдельного запроса «да» для консультации. Это уведомление не записывается как согласие. Подтверждение передачи заявки сохранено отдельно.
AlfaCRM: создание лида по прежней настройке; реальная запись на конкретное место ещё не реализована.
Ограничения Telegram не обходятся; автоповтора после ошибки нет.
Пройдено 59 локальных тестов. Живая проверка Telegram/OpenAI/CRM требует запуска с вашими ключами.

4.12: После подтверждения передачи заявки оба директора получают Telegram-ссылку и сведения о заявке. Если username отсутствует — Telegram ID. Повторных автоматических уведомлений по той же заявке нет; неопределённая доставка отмечается в журнале.
Для AlfaCRM в .env: CRM_ENABLED=true; ALFACRM_ALEX_URL, ALFACRM_ALEX_EMAIL, ALFACRM_ALEX_API_KEY, ALFACRM_ALEX_BRANCH. Для Ярославля — аналогичные YARO. SAFE_TEST_MODE=true запрещает реальные заявки и уведомления. Создаётся лид, не бронь места. При совпадении телефона используется существующая карточка.
Проверка: 63 локальных теста; работа с вашей CRM требует проверки подключения. Для повторной синхронизации сохранённых заявок: python main.py retry-crm.
