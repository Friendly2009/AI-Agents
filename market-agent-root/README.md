# Market Agent 0.3 · MOEX + новости + Gemini

Локальный сервис на Python 3.11+: 20 акций MOEX, новости, профиль инвестора и условный план «купить / продать / ждать» с количеством акций. Веб-интерфейс, SQLite и API для внешнего дашборда. **Сделки не исполняются.**

## Запуск на Windows

1. Распакуйте архив в новую папку. Остановите старую версию через `Ctrl+C`.
2. При обновлении скопируйте из старой папки **только `.env` и `data`** в новую, чтобы сохранить ключ, токен и историю. Не переносите `.venv`: окружение создастся заново. Если DATABASE_PATH нестандартный, перенесите соответствующий файл БД и проверьте путь.
3. Запустите `START_WINDOWS.cmd`. Нужен установленный Python 3.11+ с командой `python` в PATH. Скрипт создаст окружение и установит зависимости. При следующих запусках установленной 0.3 повторная установка пропускается.
4. При первом запуске настройка попросит ключ Gemini и модель. Вставка ключа скрыта — это нормально. Если `.env` уже настроен, ключ повторно не запрашивается и модель не заменяется автоматически.
5. Откройте **http://127.0.0.1:8000**, войдите с **API_TOKEN из `.env`**, а не ключом Gemini.
6. Заполните «Ваши условия», нажмите «Сохранить условия», затем «Проверить подключения» и «Запустить анализ».

Команды вручную из новой папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m market_agent setup
.\.venv\Scripts\python.exe -m market_agent serve
```

**Не запускайте `python -m venv .venv` повторно внутри уже активированного `.venv`.** Для обычного запуска нужен только `START_WINDOWS.cmd` или последняя команда. Не обновляйте pip ради запуска проекта.

Linux/macOS: `python3 -m venv .venv`, затем `.venv/bin/python -m pip install -e '.[dev]'`, `.venv/bin/python -m market_agent setup`, `.venv/bin/python -m market_agent serve`.

Для замены ключа/модели остановите сервер и выполните:

```powershell
.\.venv\Scripts\python.exe -m market_agent setup --force
```

Новый архив не содержит ключей, базы или окружения. `.env.example` включён. Настройка создаёт случайный API_TOKEN, записывает ключ локально, сохраняет имеющийся токен и путь БД. После изменений `.env` перезапустите сервер.

## Условия для рекомендаций

- **Свободные деньги:** сумма на новые покупки в рублях, без стоимости текущих акций.
- **Горизонт:** 7–365 дней. Это срок идеи; расчётные цены нужно перепроверять перед сделкой.
- **Риск:** осторожный, умеренный, высокий; числовые лимиты показаны в форме.
- **Портфель:** отметьте полноту и перечислите все текущие позиции в штуках, не лотах. Если акций нет, отметьте полноту и оставьте список пустым. Вводятся только бумаги из настроенного списка; расширьте конфигурацию, если у вас есть другие акции. Не обозначайте неполный портфель как полный.
- **Пожелания:** обычный текст, например «предпочитаю компании с понятным бизнесом». Он передаётся модели как контекст. Жёсткие числовые ограничения задаются структурированными полями; свободный текст не становится гарантированным программным запретом.

Профиль хранится в SQLite, а не в `.env`. Он общий для этой установки; аккаунтов нескольких пользователей нет. Снимок профиля сохраняется внутри каждого отчёта, поэтому изменение условий не переписывает старые планы. Несохранённые изменения блокируют ручной запуск в интерфейсе. Расписание использует последний сохранённый профиль.

Если портфель неизвестен, покупки помечаются как **модельный сценарий**, продажи не рассчитываются. Для продажи нужно вручную указать текущие акции. После реальных сделок обновляйте свободные деньги и позиции: подключения к брокерскому счёту и учёта исполнения нет.

## Что происходит при анализе

1. Код получает дневные свечи MOEX за 400 календарных дней (90 для старого режима обзора без профиля), исключая текущий день. Получает размер лота и валюту из справочника MOEX.
2. Собирает заголовки/краткие описания RSS, отбирает свежие новости по тикерам и названиям компаний. Полные статьи и финансовая отчётность не скачиваются.
3. Считает недельное изменение, SMA20, SMA60, ATR14 как среднее true range за 14 периодов, относительный объём и приблизительный оборот как close × volume.
4. Акции с достаточными данными отправляются **одним запросом** Gemini вместе с профилем и ограничениями. Модель выбирает buy/sell/wait, долю продажи и объясняет основания, возражения и условия пересмотра. Количества и цены модель не назначает.
5. Код проверяет JSON, полноту списка и принадлежность ссылок акциям. Рассчитывает количество, округляет до целых лотов, применяет общий бюджет и ограничения риска. Непрошедшее проверку предложение превращается в «ждать» с объяснением.

Новости и котировки запрашиваются напрямую: **ключ Gemini для них не нужен**. Он нужен только для интерпретации моделью. Профиль, позиции, пожелания и выбранные данные отправляются настроенному LLM-провайдеру. Программа не переключает тариф и не выбирает платную модель автоматически.

### Правила расчёта `allocation-1`

Это прозрачные инженерные ограничения, **не проверенная на истории прибыльная стратегия**:

| Профиль | Макс. доля одной бумаги в капитале | Макс. доля свободных денег на все покупки | Расчётный риск новой идеи | Расчётный риск всех новых покупок |
|---|---:|---:|---:|---:|
| Осторожный | 10% | 40% | 0,5% капитала | 2% капитала |
| Умеренный | 15% | 70% | 1% капитала | 3% капитала |
| Высокий | 20% | 90% | 2% капитала | 5% капитала |

Капитал = свободные деньги + оценка введённых акций по последнему закрытию. При неполной оценке портфеля покупки блокируются. Существующее превышение лимита позиции само по себе не создаёт продажу.

Для числового плана нужны ≥60 сессий, ATR14 > 0, котировки не старше семи календарных дней, подтверждённый лот/рублёвая валюта, приблизительный дневной оборот ≥1 млн ₽ и хотя бы одна подходящая новость. Покупка дополнительно требует close > SMA20 ≥ SMA60. Очередь распределения бюджета: недельное изменение по убыванию, затем тикер; это не оценка вероятности успеха.

Диапазон проверки покупки — ±1% от последнего закрытия. Количество рассчитывается по верхней цене с резервом комиссии 0,1%. Уровень пересмотра — закрытие минус max(3% цены, 2 × ATR14); при расстоянии ≥20% покупка отклоняется. Количество ограничено свободным бюджетом, остатком лимита позиции и расчётным риском до уровня пересмотра с резервом комиссии. Доли продажи — четверть, половина или вся введённая позиция, округлённые вниз до лота; дробный остаток не продаётся. Будущая выручка от продаж не расходуется на покупки. Шорты и кредит не поддерживаются.

**Риск здесь относится только к новым покупкам, не к максимальной потере всего портфеля.** Стоп не выставляется; гэп может увеличить убыток. План требует пересмотра не позднее 24 часов после формирования, при выходе цены из диапазона и после изменения портфеля. Свечи не корректируются на дивиденды и сплиты; отдельного биржевого календаря нет. Нужна ручная проверка корпоративных событий и актуальной цены.

При отсутствии ИИ или данных «ждать, 0 шт.» означает, что рекомендация не сформирована; причина видна в карточке. `ai_complete=false` означает неполный анализ моделью, даже если часть бумаг получила план. Ошибки одной бумаги не заменяются вымышленными данными.

## Источники

`markets.live.json` содержит SBER, GAZP, LKOH, ROSN, NVTK, TATN, SNGS, GMKN, PLZL, CHMF, NLMK, MAGN, ALRS, MGNT, MTSS, MOEX, PHOR, IRAO, HYDR, RUAL; MOEX ISS, TQBR.

RSS: `https://www.vedomosti.ru/rss/rubric/business` и `https://www.vedomosti.ru/rss/rubric/finance`. Полнота покрытия ограничена этими лентами и совпадением ключевых слов. На акцию передаётся до 10 релевантных новостей за последние 7 дней. Архив накапливается при работающем сервисе, опрос каждые 30 минут и перед анализом, хранение 35 дней. На первом запуске невозможно восстановить новости, уже исчезнувшие из RSS. Проверьте источники и период до оценки качества рекомендаций.

## `.env` — настройки сервиса

| Поле | Назначение |
|---|---|
| API_TOKEN | Случайный секрет для входа в этот сервис; минимум 32 символа |
| LLM_API_KEY | Ключ Gemini из вашего проекта, не API_TOKEN |
| LLM_ENABLED | `true` для ИИ; `setup` включает автоматически |
| LLM_BASE_URL | `https://generativelanguage.googleapis.com/v1beta/openai` — базовый адрес API, не страница для браузера |
| LLM_MODEL | По умолчанию `gemini-3.8-flash`; доступ зависит от провайдера и проекта |
| MODE | `live` — внешние данные, `demo` — синтетические без ИИ/торговых рекомендаций |
| MARKETS_FILE | `markets.live.json`: список бумаг, их ключевые слова и RSS |
| DATABASE_PATH | SQLite: отчёты, новости, профиль |
| TIMEZONE | `Europe/Moscow` |
| SCHEDULE_ENABLED | Автоматический недельный анализ |
| SCHEDULE_WEEKDAY/HOUR/MINUTE | `0/9/0` — понедельник 09:00 |
| SCHEDULE_CATCHUP | Догнать текущий недельный анализ после включения |
| NEWS_LOOKBACK_DAYS | Период новостей, 7 дней по умолчанию |
| NEWS_COLLECTION_ENABLED / NEWS_POLL_MINUTES | Фоновый сбор / интервал, по умолчанию true / 30 |
| HTTP_TIMEOUT_SECONDS / HTTP_RETRIES | Тайм-аут источников / ограниченные повторы GET |
| LLM_TIMEOUT_SECONDS | Ожидание ответа модели, по умолчанию 90 секунд |
| CORS_ORIGINS | JSON-массив origin внешнего браузерного дашборда |

Кавычки вокруг значений допустимы. Пояснения начинайте с `#`, лучше отдельной строкой. Не дописывайте обычный русский текст после значения без `#`. Секреты не присылайте в чат и не включайте в публичный код.

## Ошибки и диагностика

```powershell
.\.venv\Scripts\python.exe -m market_agent doctor
.\.venv\Scripts\python.exe -m market_agent doctor --no-llm
```

Первая команда делает один короткий запрос к модели; вторая проверяет источники без расхода квоты ИИ. Проверка доступности не гарантирует, что большой отчёт укладывается в квоту/тайм-аут.

- **503 / high demand:** перегрузка провайдера. Новый код не устраняет её. План делает максимум три попытки только при явном HTTP 503, затем сохраняет данные без числовых сделок. Диагностика делает одну попытку.
- **429:** квота или частота; проверьте ограничения проекта и повторите позже.
- **401 / API key not valid:** неверный ключ или доступ.
- **403 / регион:** доступность сервиса и разрешения проекта.
- **404:** неверная/недоступная модель или адрес. Открытие BASE_URL в браузере не проверяет Chat Completions API.
- **Неверная схема ответа:** модель не соблюла формат; числовой план не рассчитывается.

POST после сетевого тайм-аута не повторяется автоматически: предыдущий запрос мог уже расходовать квоту. Подписка ChatGPT Plus не предоставляет баланс для API; OpenAI API подключается и оплачивается отдельно.

## Расписание и работа

Терминал должен оставаться открытым, компьютер — включённым. До сохранения профиля расписание формирует только общий обзор без персонального плана. `SCHEDULE_CATCHUP=true` может сразу запустить пропущенный анализ текущей недели при старте, включая запросы ИИ. Для настройки без автоматических запусков временно задайте `SCHEDULE_ENABLED=false`.

Ручной запуск не заменяет недельный. Полный сбой повторяется до трёх раз с интервалом не менее 15 минут от начала попытки. Частичный отчёт считается завершённым: после исправления запустите вручную. Лимит анализа — 10 минут, аварийная блокировка — 11 минут. Один процесс/worker, локальная SQLite. Пример Linux-службы — `deploy/market-agent.service`. Уведомления Telegram/email не реализованы.

## Встраивание в дашборд

Готов JSON API; интеграция с конкретным дашбордом потребует подключения его интерфейса к этим маршрутам. Все `/api/*` требуют `Authorization: Bearer <API_TOKEN>`.

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/profile` | Сохранённый профиль и числовые правила риска |
| POST | `/api/profile` | Сохранить условия и позиции |
| POST | `/api/runs` | Запустить анализ: 202 + id; 409 при активном анализе |
| GET | `/api/runs?limit=30` | История |
| GET | `/api/runs/{id}` | Статус и отчёт |
| GET | `/api/config` | Настройки без секретов |
| GET | `/api/status` | Сбор новостей и последняя диагностика |
| POST | `/api/check` | Проверить подключения |
| GET | `/api/openapi.json` | OpenAPI-схема |

Пример тела `POST /api/profile` (демонстрация формата, не инвестиционная рекомендация):

```json
{"cash_rub":100000,"horizon_days":90,"risk":"balanced","portfolio_known":true,"holdings":[{"symbol":"SBER","shares":100}],"notes":"Предпочитаю подробное объяснение рисков"}
```

Затем POST `/api/runs` и опрос ID каждые 2–5 секунд до `completed`, `degraded` или `failed`. `schema_version=2`: `report.profile` содержит снимок условий, `allocation` — общие суммы, `instruments[].recommendation` — итоговый action, предложенный proposed_action, shares, lots, суммы и причины. Старые отчёты могут не иметь новых полей. ИИ не имеет доступа к выполнению API-команд.

Храните API_TOKEN на backend дашборда. Для доверенного отдельного браузерного frontend задайте точные CORS_ORIGINS, например `["https://dashboard.example.com"]`. Cross-origin iframe запрещён CSP. Для публикации нужен HTTPS и контроль доступа. **Это одна установка с одним профилем и общим токеном; для разных клиентов нужны отдельные аккаунты, профили и изоляция данных, пока не реализованные.**
