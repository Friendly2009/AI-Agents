Новые сценарии: профиль и его сохранение, неизвестные/повторные тикеры, некорректные бюджеты и позиции, общий бюджет 20 бумаг для трёх уровней риска и четырёх бюджетов, лимиты позиции и риска, целые лоты, отсутствие коротких продаж, частичная продажа, запрет расходовать будущую выручку, неоценённые позиции, устаревшие данные, короткая история, низкий оборот, нет новостей/лота/ИИ, отклонение покупки по тренду.

HTTP MockTransport проверяет неизвестные ссылки и тикеры, дубли, неполный JSON, выдуманные поля количества, обрезанный ответ, ограниченные повторы 503 без раскрытия ключа. Полный интеграционный сценарий с моделью-заглушкой проверяет один пакетный запрос по двум акциям, расчёт покупок, сохранение отчёта и неизменность снимка профиля при параллельном обновлении условий.

Одно предупреждение Starlette касается использования httpx в TestClient; тесты проходят. Это не ошибка рабочего сервиса.

## Реальные внешние запросы без LLM-ключа

Все **20 из 20** настроенных акций MOEX вернули справочник (лот и рублёвую валюту) и дневные свечи за 400 календарных дней. Последняя сессия во всех ответах — **2026-10-13**, по 363–367 свечей. Размеры лотов считаны из ответа биржи, не заданы константами. Например: SBER — 1, GAZP — 10, HYDR — 1000.

Обе RSS-ленты «Ведомостей» прочитаны и сохранены в SQLite без предупреждений: **128 записей**. Отбор на момент проверки: SBER — 4 новости, GAZP — 2, LKOH — 3, NVTK — 1, остальные 16 бумаг — 0. При нулевом новостном покрытии код намеренно не формирует числовые сделки. Значения меняются со временем и накоплением архива.

Это проверка HTTP, парсинга, фильтрации и хранения, а не независимое подтверждение достоверности каждой публикации.

## Браузер

Проверено на работающем локальном API с временной SQLite, demo-режимом и выключенным ИИ:

- отказ с неверным токеном и вход с правильным;
- форма денег/горизонта/риска, добавление и удаление позиции;
- сохранение профиля через настоящий API и восстановление после перезагрузки;
- запрет ручного запуска до сохранения профиля и при несохранённых изменениях;
- диагностика и запуск demo-отчёта по 20 бумагам;
- в demo отсутствуют действия buy/sell;
- история и отображение снимка профиля;
- отдельная фикстура для проверки отображения buy/sell, количества, лотов и диапазона цены (это НЕ настоящий ответ модели);
- мобильная ширина 390 px без горизонтального переполнения страницы;
- выход, очистка токена; JavaScript-ошибок нет.

Десктопная и мобильная формы просмотрены визуально. Скриншоты не входят в архив.

Повторяемый сценарий: `qa/browser-check.cjs`. Он сам запускает demo-сервер на порту 8765 с временной БД и тестовым токеном; пользовательский профиль не меняет. Требует Node.js и Playwright с Chromium (`npm install --no-save playwright`, `npx playwright install chromium`). Запуск из корня проекта: `node qa/browser-check.cjs`. По умолчанию используется Python из `.venv`; для другой установки предусмотрены `QA_PYTHON` и `CHROMIUM_EXECUTABLE`.
