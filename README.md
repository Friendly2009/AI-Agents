# Weekly Market Agent · Python MVP

Локальный сервис для недельного обзора выбранных инструментов. Python 3.11+, FastAPI, SQLite, простой браузерный интерфейс и JSON API для будущего дашборда.

## Что реализовано

- Ручной анализ и запуск по расписанию (по умолчанию понедельник 09:00, Europe/Moscow).
- Реальный адаптер **MOEX, рынок акций, заданная торговая площадка**; стартовые примеры SBER/GAZP, TQBR. Другие биржи пока требуют отдельного адаптера. Выбор MOEX — технический стартовый вариант, его ещё нужно согласовать с заказчиком.
- Дневные OHLCV-свечи за 90 календарных дней. Текущий незакрытый день исключается.
- Недельное изменение цены, SMA20 и объём последней сессии относительно предыдущих 20 доступных сессий.
- RSS/Atom-новости: даты, исключение дублей, фильтрация по тикеру и ключевым словам, ссылки. Используются заголовки и краткие описания из лент, не полный текст статей.
- Официальный обзор на русском через API формата Chat Completions; проверка JSON и идентификаторов источников.
- Если ИИ выключен/недоступен — явно отмеченная расчётная сводка. Пустые новости и устаревшие цены не скрываются.
- Сохранение отчётов и ошибок, защита токеном, предотвращение одновременных запусков, повторы временных HTTP-ошибок.
- Демо-режим без сетевых запросов и расходов. Синтетические данные всегда помечены.

## Быстрый запуск на Windows (PowerShell)

Распакуйте архив, откройте терминал в папке `market-agent`:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe -m market_agent init
.\.venv\Scripts\python.exe -m market_agent serve
```

Откройте http://127.0.0.1:8000. Скопируйте `API_TOKEN` из созданного `.env` в поле подключения. Нажмите «Запустить анализ». В демо-режиме отчёт имеет статус «Готов с замечаниями» из-за синтетических данных и отсутствия настоящих новостей — это ожидаемо.

`init` создаёт случайный ключ и не перезаписывает существующий `.env`. Python должен быть версии 3.11 или новее. Если команда `py` недоступна, используйте `python`.

## Ubuntu / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python -m pip install --no-deps -e .
.venv/bin/python -m market_agent init
.venv/bin/python -m market_agent serve
```

Всегда запускайте команды из корня проекта. Пакет включает интерфейс; `.env`, файл инструментов и БД располагаются относительно рабочего каталога.

Для разработки вместо фиксированных зависимостей можно установить `pip install -e '.[dev]'`.

## Подключение реальных данных и ИИ

1. Скопируйте `markets.example.json` в `markets.json`.
2. Укажите согласованные инструменты MOEX и реальные адреса RSS/Atom-лент в `news_feeds`. Пустой список разрешён, но отчёт явно сообщит, что новостей нет. Лента должна содержать дату с часовым поясом и абсолютную HTTP(S)-ссылку. URL переадресации не обрабатываются: укажите конечный адрес ленты.
3. В `.env` выставьте `MODE=live` и `MARKETS_FILE=markets.json`.
4. Для ИИ выставьте `LLM_ENABLED=true`, задайте `LLM_API_KEY`, `LLM_MODEL` и `LLM_BASE_URL`. Модель должна поддерживать Chat Completions и `response_format={"type":"json_object"}`. Пример базового URL Gemini уже есть в `.env.example`; ID модели выберите из доступных в вашем аккаунте. Ключей в архиве нет.
5. Перезапустите процесс и запустите пробный анализ кнопкой. Проверьте даты, найденные новости и пометку «Интерпретация ИИ».

Пример структуры конфигурации (адреса RSS заполните настоящими ссылками выбранного источника):

```json
{
  "instruments": [
    {"exchange": "MOEX", "symbol": "SBER", "board": "TQBR", "keywords": ["Сбербанк", "Сбер", "Sber"]}
  ],
  "news_feeds": []
}
```

До 50 инструментов и 10 лент. Ключевые слова сопоставляются без учёта регистра по границам слов, без морфологии: при необходимости добавьте варианты названий. Новости отбираются из последних 7 дней (параметр `NEWS_LOOKBACK_DAYS`), максимум 10 записей на инструмент. Ленты часто содержат только свежие записи: сервис не восстанавливает отсутствующий недельный архив. Для полного покрытия недели нужен источник с достаточной историей или дополнительный ежедневный сборщик.

Модель получает показатели и выбранные краткие новости. Новостной текст считается недоверенным, инструменты выполнения кода/сделок модели не предоставляются. Проверка source_ids предотвращает неизвестные идентификаторы в структурированном поле, но не доказывает достоверность каждого предложения модели. Сравните первый настоящий отчёт с источниками вручную.

## Расписание и восстановление

Процесс должен работать в назначенное время и иметь интернет. Отдельный постоянно работающий сервер нужен только если компьютер Андрея не будет включён. Настройки: `SCHEDULE_ENABLED`, `SCHEDULE_WEEKDAY` (0=понедельник), `SCHEDULE_HOUR`, `SCHEDULE_MINUTE`, `TIMEZONE`.

При `SCHEDULE_CATCHUP=true` пропущенный запуск выполняется после включения в пределах текущего недельного окна. История завершённых недель хранится в SQLite, рестарт не вызывает повтор завершённой недели. При `false` запуск возможен только в назначенный день после указанного времени. Старые недели пачкой не восстанавливаются.

Полностью неудачный недельный запуск повторяется до 3 попыток, не чаще чем раз в 15 минут от начала предыдущей попытки. Частичный отчёт (`degraded`) считается завершённым; после исправления источника используйте ручной запуск. Он не заменяет недельный запуск и хранится отдельной записью. После исчерпания попыток нужен ручной запуск или следующая неделя. При аварии активная блокировка устаревает через 11 минут; анализ ограничен 10 минутами. Статус старого запуска меняется при следующей попытке запуска.

База использует атомарную блокировку для одного анализа за раз. Для этой версии запускайте **один процесс Uvicorn, один worker**, с локальной файловой SQLite. Файл БД нельзя размещать на сетевой файловой системе. Пример автозапуска Ubuntu — `deploy/market-agent.service`: создайте отдельного пользователя `market-agent`, разместите проект в `/opt/market-agent`, создайте каталог `data` и выдайте этому пользователю права на него; `.env` должен быть ему доступен на чтение. Затем настройте пути unit-файла перед установкой. Сам пример ничего в системе не устанавливает.

## API для внешнего дашборда

Все `/api/*` требуют `Authorization: Bearer <API_TOKEN>`. `/` — оболочка входа, `/health` — только состояние процесса.

| Метод | URL | Результат |
|---|---|---|
| GET | `/api/config` | Публичные настройки без секретов |
| POST | `/api/runs` | 202 и `{id,status}`; 409 если анализ уже идёт |
| GET | `/api/runs?limit=30` | До 100 последних запусков, новые сверху |
| GET | `/api/runs/{id}` | Статус, ошибка или полный сохранённый отчёт |
| GET | `/api/openapi.json` | Машиночитаемая OpenAPI-схема |

После POST опрашивайте GET по ID раз в 2–5 секунд до статуса `completed`, `degraded` или `failed`. Схема отчёта имеет `schema_version: 1`, массив `instruments`, метрики, свечи, источники, summary, `analysis_kind`, warnings и признак `mode`. Реальный и демонстрационный отчёты различаются этим полем.

Для своего дашборда предпочтителен серверный запрос с ключом. Не встраивайте постоянный ключ в публичный JavaScript. Для доверенного отдельного браузерного интерфейса задайте точные `CORS_ORIGINS=["https://dashboard.example.com"]` и ввод ключа пользователем. Встроенный интерфейс хранит ключ только в оперативной памяти вкладки. Сейчас cross-origin iframe запрещён CSP: интеграция предусмотрена через API, платформу заказчика ещё нужно согласовать.

Локальный запуск по умолчанию слушает 127.0.0.1. При размещении на сервере используйте HTTPS reverse proxy и отдельную авторизацию пользователей при необходимости: текущий API_TOKEN — один общий ключ владельца, без ролей и многопользовательских аккаунтов. Уведомления во внешние сервисы не реализованы: результат появляется в истории и API.

## Командная строка и тесты

```bash
python -m market_agent analyze
python -m pytest -q
ruff check --config pyproject.toml .
```

`analyze` запускает один анализ, сохраняет результат в БД и выводит JSON; код выхода 1 при полном сбое. Не запускайте его одновременно с серверным анализом. Не помещайте полученный live-отчёт в публичный репозиторий без проверки содержимого.

Автотесты не расходуют API-кредиты: внешние ответы подменяются HTTP MockTransport. Проверяются расчёты, пагинация MOEX, XML/RSS/Atom, даты и дубли, ошибки/повторы, JSON модели и неизвестные ссылки, частичные сбои, устаревшие цены, расписание, конкурентные запуски, восстановление, авторизация и API end-to-end. Результаты фактического прогона — `TEST_RESULTS.md`.

## Границы первой версии

- Поддержаны акции MOEX. Binance/NYSE/NASDAQ и произвольные биржи не включены.
- Выводы — обзор доступных цен и новостей; торговые поручения, портфель, backtesting и обещания точных прогнозов отсутствуют.
- Цены MOEX не корректируются здесь на сплиты/дивиденды. Корпоративные события могут искажать изменение и SMA; сравнивайте с первоисточником.
- Недельное изменение: последняя закрытая цена относительно последней доступной цены не позднее чем за 7 календарных дней до неё. Даты обеих точек выдаются в API. SMA20 требует 20 сессий, иначе null.
- Нет полноценного календаря биржи; более 7 календарных дней без свежих свечей вызывает предупреждение.
- ИИ может ошибаться; исходные ссылки и расчёты сохраняются для проверки. До приёмки согласуйте образец отчёта, перечень инструментов, новости и критерии качества с Андреем.

Официальные спецификации: [MOEX ISS](https://www.moex.com/a2193), [Gemini Chat Completions compatibility](https://ai.google.dev/gemini-api/docs/openai), [FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events/).
