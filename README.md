# Market Agent 0.2 · MOEX + новости + Gemini

Личный аналитический сервис для Андрея: SBER и GAZP на Московской бирже, новости из RSS «Ведомостей», недельный отчёт через Gemini, интерфейс и API для дашборда. Python 3.11+; FastAPI; SQLite. Реальные новости и котировки проверены при сборке. Настоящий ответ Gemini нужно проверить с ключом вашего аккаунта.

## Обновление с версии 0.1 — Windows

1. Остановите сервер (`Ctrl+C`).
2. Скопируйте содержимое папки `market-agent` из архива в существующую папку с заменой файлов. **Не удаляйте `.env`, `.venv` и `data`**. В архиве нет этих файлов/каталогов; они сохранятся при обычном копировании.
3. Выполните в PowerShell из папки проекта:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m market_agent setup
.\.venv\Scripts\python.exe -m market_agent serve
```

Настройка попросит **ключ Gemini** скрытым вводом (при вставке символы не отображаются — это нормально), затем предложит модель `gemini-2.5-flash`: нажмите Enter, чтобы оставить её. Сервис сохранит ключ в локальном `.env`, включит настоящий режим и готовую конфигурацию источников. API_TOKEN, путь к базе и ваше расписание сохраняются. Дополнительные акции из старой конфигурации не удаляются, но активным становится `markets.live.json` с SBER/GAZP: при необходимости перенесите изменения туда.

Откройте **http://127.0.0.1:8000**. Вход — прежний `API_TOKEN` из `.env`, **не ключ Gemini**. Нажмите «Проверить подключения», затем «Запустить анализ». Проверка подключения использует один небольшой запрос к модели. Настоящий отчёт должен показывать «Интерпретация ИИ», дату котировок, новости и ссылки. Старые демо-отчёты останутся в истории.

Не присылайте `.env` и ключи в чаты. Если вы используете Free Tier, ключ должен принадлежать проекту с соответствующей квотой. Приложение не включает/не выключает биллинг Google и не умеет определить тариф проекта. Наличие ключа не гарантирует доступную квоту или поддержку региона.

## Первый запуск

На Windows можно дважды нажать `START_WINDOWS.cmd`: он создаёт окружение при отсутствии, устанавливает пакет без обновления pip, запускает настройку и сервис. Если компьютер не знает команду `python`, сначала установите Python 3.11+ и добавьте его в PATH.

Команды вручную:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m market_agent setup
.\.venv\Scripts\python.exe -m market_agent serve
```

Ubuntu/macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m market_agent setup
.venv/bin/python -m market_agent serve
```

Запускайте из корня проекта. На Windows активация окружения не нужна. Закрытие браузера не останавливает сервис; закрытие терминала/выключение компьютера останавливает анализ и сбор новостей. `Ctrl+C` — остановить.

## Реальные источники

Файл `markets.live.json` уже заполнен:

- **Котировки:** MOEX ISS, рынок акций, режим TQBR, SBER и GAZP. Запрашиваются дневные OHLCV-свечи за 90 календарных дней, текущий незакрытый день исключается.
- **Новости:** `https://www.vedomosti.ru/rss/rubric/business` и `https://www.vedomosti.ru/rss/rubric/finance`. Источники прошли реальный HTTP и XML-прогон. Сохраняются заголовки, краткие описания, даты и ссылки; полный текст статей не скачивается.
- **ИИ:** Gemini через совместимый Chat Completions API. Модель по умолчанию — `gemini-2.5-flash`. Другую доступную модель можно задать в `.env` или при повторной настройке.

Новости фильтруются по тикеру и явно заданным вариантам названия компании. На инструмент в модель передаётся до 10 свежих релевантных записей. Модель не имеет инструментов для посещения сайтов или исполнения сделок: получает уже собранные данные. Пустые результаты не заменяются выдуманными новостями.

Сервис опрашивает ленты при запуске, затем каждые **30 минут** и перед отчётом (повтор в пределах двух минут использует недавний результат). В SQLite накапливается архив, удаляются записи старше 35 дней. Отчёт выбирает новости за последние 7 дней. Сбой одной ленты не стирает уже собранные новости. Изменение набора лент исключает старые источники из выборки. Даты публикаций сохраняются, не заменяются датой загрузки.

**На первом запуске полнота недели ограничена историей самих RSS.** Если компьютер выключен, пропущенные записи, уже исчезнувшие из ленты, восстановить нельзя. В отчёте показывается начало накопления архива. Для постоянного сбора сервис должен работать на включённом компьютере или сервере.

Официальные источники: [MOEX ISS](https://www.moex.com/a2193), [RSS «Ведомостей»](https://www.vedomosti.ru/info/rss), [Gemini API compatibility](https://ai.google.dev/gemini-api/docs/openai), [тарифы и Free Tier](https://ai.google.dev/gemini-api/docs/pricing).

## Что выдаёт отчёт

Для каждой акции: последние закрытые цены, график 30 сессий, изменение за неделю, SMA20, относительный объём, выбранные новости и официальный комментарий ИИ с рисками. Исходные свечи и ссылки доступны в API.

Недельное изменение — последняя закрытая цена относительно последней доступной цены не позднее чем за 7 календарных дней до неё. Обе даты сохраняются. SMA20 требует 20 сессий, иначе null. Относительный объём — объём последней сессии относительно среднего до 20 предыдущих сессий.

Если модель недоступна, результат явно обозначен как расчётная сводка; `ai_complete=false` и статус `degraded`. При ошибках ключа/квоты последующие акции в том же отчёте не вызывают заведомо неработающую модель. Автоматических повторов POST к модели нет, чтобы не тратить квоту после неоднозначного сбоя сети. Программа не переключается на платную модель автоматически.

Цена и показатели считаются кодом, модель объясняет входные данные. Проверка JSON и source_ids отсеивает неизвестные идентификаторы источников, но не доказывает каждую фразу модели. Изменения цен не корректируются на сплиты/дивиденды; календарь биржи отдельно не реализован, давность более 7 дней вызывает предупреждение. Это аналитический обзор, без торговых поручений, портфеля, backtesting и обещаний доходности.

## Настройки .env

| Параметр | Назначение |
|---|---|
| API_TOKEN | Секрет для доступа к вашему сервису; не ключ Gemini |
| MODE | `live` — реальные данные; `demo` — синтетические, без сетевых запросов |
| MARKETS_FILE | `markets.live.json`; список акций и RSS |
| DATABASE_PATH | SQLite с отчётами, новостями и попытками сборов |
| TIMEZONE | `Europe/Moscow` |
| SCHEDULE_ENABLED | Автоматический недельный отчёт |
| SCHEDULE_WEEKDAY/HOUR/MINUTE | `0/9/0`: понедельник 09:00 |
| SCHEDULE_CATCHUP | Выполнить пропущенный недельный отчёт при включении в текущем недельном окне |
| NEWS_LOOKBACK_DAYS | Период новостей, по умолчанию 7 дней |
| NEWS_COLLECTION_ENABLED | Фоновый сбор новостей при работающем сервере |
| NEWS_POLL_MINUTES | Интервал фонового сбора, по умолчанию 30 минут |
| HTTP_TIMEOUT_SECONDS / HTTP_RETRIES | Ожидание источника / повторы GET при временном сбое |
| LLM_ENABLED | Включён ли ИИ; setup устанавливает true |
| LLM_API_KEY | Ваш ключ Gemini, хранится локально |
| LLM_BASE_URL | `https://generativelanguage.googleapis.com/v1beta/openai` |
| LLM_MODEL | По умолчанию `gemini-2.5-flash` |
| LLM_TIMEOUT_SECONDS | Ожидание ответа ИИ, 90 секунд |
| CORS_ORIGINS | Разрешённые origin внешнего браузерного дашборда, JSON-массив |

После ручного изменения настроек перезапустите сервер. `.env.example` — шаблон, `.env` — настоящие настройки. `.env` и `data` игнорируются Git. `setup --force` позволяет сменить ключ/модель; действующие настройки перезаписываются атомарно только после проверки. История БД обновляется добавлением таблиц, старые отчёты сохраняются.

## Диагностика и ошибки

```powershell
.\.venv\Scripts\python.exe -m market_agent doctor
.\.venv\Scripts\python.exe -m market_agent doctor --no-llm
```

Первая команда проверяет MOEX, RSS и один настоящий JSON-ответ Gemini; вторая не расходует квоту ИИ. То же с ИИ доступно кнопкой «Проверить подключения».

| Сообщение | Что проверить |
|---|---|
| Ключ API не принят | LLM_API_KEY и проект Google AI Studio |
| HTTP 429 | Остаток квоты/лимиты проекта; повторить позже |
| Регион не поддерживается | Официальную доступность Gemini в месте отправки запроса |
| Модель не найдена | Доступность LLM_MODEL в вашем аккаунте |
| Временная ошибка сервиса | Повторить позже, проверить состояние провайдера |
| Источник недоступен | Интернет, настройки прокси, доступ к источнику |
| ИИ выключен | Выполнить setup и перезапустить сервер |

В диагностике не выводятся ключи, Authorization или сырые тела ошибок провайдера. Полученные новости — недоверенные данные; модель инструктирована не выполнять инструкции из них, интерфейс выводит текст безопасно через textContent.

## Расписание и эксплуатация

По умолчанию понедельник 09:00 по Москве. С `SCHEDULE_CATCHUP=true` первое включение во вторник может сразу создать пропущенный недельный отчёт — это ожидаемо и использует запросы Gemini. Завершённая неделя не запускается повторно после рестарта. Старые недели пачкой не догоняются. Ручные отчёты отдельные и не заменяют недельный.

Полный сбой повторяется до 3 раз, не чаще 15 минут от начала предыдущей попытки. Частичный отчёт `degraded` считается завершённым; после исправления подключения запустите вручную. Анализ ограничен 10 минутами; аварийная блокировка устаревает через 11 минут и очищается при следующей попытке запуска.

Один процесс и один Uvicorn worker. SQLite на локальном диске. Для Ubuntu дан пример `deploy/market-agent.service`; создайте пользователя `market-agent`, каталог `/opt/market-agent/data` с правами записи для него, настройте пути, установите зависимости и `.env`. Unit-файл сам ничего не устанавливает. При публикации через домен нужен HTTPS reverse proxy; текущий токен предназначен для одного владельца, многопользовательские роли не реализованы.

## Подключение к дашборду

Все `/api/*` защищены заголовком `Authorization: Bearer <API_TOKEN>`. `/health` показывает только доступность процесса. Дашборд может получить полный отчёт и нарисовать собственные карточки.

| Метод | URL | Действие |
|---|---|---|
| POST | `/api/runs` | Запуск анализа, 202 + ID; 409 если уже запущен |
| GET | `/api/runs?limit=30` | История; максимум 100 |
| GET | `/api/runs/{id}` | Статус и полный отчёт |
| GET | `/api/config` | Настройки без секретов |
| GET | `/api/status` | Состояние сбора новостей и последняя диагностика |
| POST | `/api/check` | Проверка котировок, новостей и Gemini; один запрос к модели |
| GET | `/api/openapi.json` | OpenAPI |

После запуска опрашивайте ID каждые 2–5 секунд до `completed`, `degraded` или `failed`. В отчёт добавлены `ai_complete` и `news_collection`; остальные поля совместимы с версией 0.1. `schema_version=1`, новые поля добавлены без удаления старых.

Предпочтительно хранить ключ на backend дашборда. Для доверенного отдельного браузерного frontend укажите точные CORS_ORIGINS, например `["https://dashboard.example.com"]`; не публикуйте постоянный ключ в исходниках. Наш UI хранит токен только в памяти вкладки. Cross-origin iframe запрещён CSP; готова интеграция через API, а не конкретный неизвестный дашборд. Внешние Telegram/email-уведомления не включены.
