# Руководство: тестирование и ввод в эксплуатацию Telegram-агента «Анастасия»

> Версия, проанализированная по исходному архиву: **4.26 RC1**. Это инструкция для
> исходной папки, полученной после распаковки `Anastasiya-AI.rar`. Файл `.env`, папка
> `data/`, Telegram-сессии и ключи API не должны попадать в Git, архивы, скриншоты или
> переписку.

## 1. Что делает сборка и её границы

«Анастасия» — Telegram-клиент на Python (Telethon), который отвечает в личных
диалогах, использует OpenAI для формирования ответов, ведёт локальные SQLite-базы и
может создавать лиды в AlfaCRM. В ней также есть локальная панель администратора.

В поставленной конфигурации включён `SAFE_TEST_MODE=true`. В таком состоянии агент:

- не делает исходящих рассылок, не ищет и не вступает в группы, не передаёт данные в CRM;
- позволяет владельцам тестировать ответы в изолированном диалоге `/диалог_тест`;
- не является «тестом на реальных клиентах»: реальные входящие личные сообщения при
  `SAFE_TEST_MODE=true` не получают обычного AI-ответа.

Не используйте чужой Telegram `tdata`, Auth Key или `.session`. В конфигурации создаётся
новая сессия `data/sessions/<TG_SESSION_NAME>.session` для отдельного, законно
контролируемого аккаунта агента. Тестировать можно только с совершеннолетними
добровольцами/клиентами, которых заранее предупредили об ИИ и которые дали согласие на
участие и обработку данных. Не запускайте массовую рассылку незнакомым людям.

## 2. Распаковка и подготовка окружения

Ниже все команды начинаются с места, куда распакован присланный архив. Примеры используют
папку `C:\Anastasiya-AI`; замените её на свою. После распаковки в ней должны быть
`src`, `scripts`, `tests`, `.env.example`, `requirements.txt`.

### Windows 10/11 (рекомендуемый вариант для этой сборки)

1. Установите **Python 3.11 или новее** с <https://www.python.org/downloads/windows/>.
   При установке отметьте **Add Python to PATH**.
2. Распакуйте `Anastasiya-AI.rar` целиком, например в `C:\Anastasiya-AI`.
3. Откройте PowerShell и выполните:

```powershell
cd C:\Anastasiya-AI
py -3 --version
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt
```

Если PowerShell запрещает активацию виртуального окружения, для текущего окна выполните
`Set-ExecutionPolicy -Scope Process Bypass`, после чего повторите строку активации. Можно
не использовать venv и дважды щёлкнуть `install_dependencies.cmd`, однако venv делает
установку изолированной и воспроизводимой.

### Ubuntu/Debian (сервер или рабочая станция)

Выполните под обычным пользователем из каталога распакованного архива:

```bash
cd /opt/Anastasiya-AI
sudo apt update
sudo apt install -y python3.11 python3.11-venv python3-pip
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt
```

Если архив распакован в домашнюю папку, сначала используйте фактический путь, например
`cd ~/Anastasiya-AI`; команда `cd /opt/Anastasiya-AI` выше — пример целевой папки.

## 3. Первичная настройка подключения

### 3.1 Создать `.env`

Из корня проекта скопируйте шаблон. В Windows это можно сделать также запуском
`setup_settings.cmd`.

```powershell
# Windows PowerShell
cd C:\Anastasiya-AI
Copy-Item .env.example .env
notepad .env
```

```bash
# Linux
cd /opt/Anastasiya-AI
cp .env.example .env
nano .env
```

### 3.2 Заполнить обязательные значения

В `.env` укажите:

| Переменная | Где получить / что указать |
| --- | --- |
| `TG_API_ID`, `TG_API_HASH` | Создать своё приложение на <https://my.telegram.org>. Это не токен BotFather. |
| `TG_PHONE` | Номер отдельного аккаунта агента в международном формате, например `+79990000000`. |
| `TG_SESSION_NAME` | Уникальное имя новой сессии, только латиница/цифры/`_`/`-`, 3–40 символов. |
| `OPENAI_API_KEY` | Секретный ключ OpenAI с включённым биллингом. |
| `OPENAI_MODEL` | Доступная вашей организации модель, по умолчанию `gpt-5-mini`. |
| `ADMIN_OWNER_TG_ID`, `ADMIN_WIFE_TG_ID` | Два разных числовых Telegram ID администраторов. Не username. |

Оставьте на первом прогоне:

```dotenv
SAFE_TEST_MODE=true
CRM_ENABLED=false
OUTREACH_ENABLED=false
AUTO_DISCOVER_GROUPS=false
AUTO_JOIN_ENABLED=false
FAMILY_RADAR_ENABLED=false
FAMILY_RADAR_OUTREACH_ENABLED=false
```

Чтобы узнать Telegram ID обоих администраторов, временно оставьте поля
`ADMIN_OWNER_TG_ID` и `ADMIN_WIFE_TG_ID` пустыми, запустите агента (шаг 5), затем каждый
из двух владельцев пишет **в личный чат аккаунта Анастасии** команду `/мой_id`. Впишите
два полученных различных числа в `.env`, остановите программу `Ctrl+C` и запустите её
заново. До заполнения двух ID директорские команды и вход в панель блокируются.

### 3.3 Офлайн-проверка

Команда не подключается к Telegram и не отправляет сообщений:

```powershell
cd C:\Anastasiya-AI
.\.venv\Scripts\Activate.ps1
python scripts\launch.py doctor
python scripts\run_tests.py
```

В Linux замените обратные слеши на обычные и активируйте `.venv/bin/activate`:

```bash
cd /opt/Anastasiya-AI
. .venv/bin/activate
python scripts/launch.py doctor
python scripts/run_tests.py
```

`doctor` проверяет формат и наличие настроек, но **не** проверяет действительность ключей
во внешних сервисах. `run_tests.py` специально запускает тесты в одноразовой копии:
не загружает рабочий `.env`, базы или Telegram-сессии и блокирует сеть. Успешные тесты —
не доказательство подключения к Telegram, OpenAI или CRM.

## 4. Запуск и подключение Telegram-аккаунта

Запускайте из корня проекта, в отдельном окне терминала:

```powershell
cd C:\Anastasiya-AI
.\.venv\Scripts\Activate.ps1
python scripts\launch.py main listen
```

При первом запуске Telethon попросит код из Telegram/SMS, а при включённой двухфакторной
защите — пароль. Вводите их только в локальном терминале. После успешного входа сессия
будет лежать в `data/sessions/`; не копируйте и не отправляйте её.

Для штатного запуска в Windows без venv также предусмотрен `start.cmd`. Проверка
настроек — `check_readiness.cmd`; панель — `start_panel.cmd`.

Остановить агента: `Ctrl+C` в окне, в котором он запущен. Не запускайте две копии из
одной папки: приложение использует блокировку `data/running.lock.db`.

## 5. Безопасное тестирование с реальными людьми

### 5.1 Подготовить пилот

1. Выделите отдельный Telegram-аккаунт Анастасии и отдельный список 3–5 взрослых
   добровольцев/действующих клиентов. Не берите номера и аккаунты из неразрешённой базы.
2. До теста отправьте участнику понятное уведомление вручную: агент автоматизирован,
   тестируется, какие данные будут обработаны, как отказаться/удалить сведения, кто
   ответственный и каков срок хранения. Получите и зафиксируйте согласие.
3. Используйте вымышленные данные там, где это возможно. Не запрашивайте паспортные,
   платёжные, медицинские и иные лишние чувствительные данные.
4. Подготовьте протокол: дата, версия кода, сценарий, ввод, ответ, ожидаемый результат,
   фактический результат, инцидент и обезличенная ссылка на доказательство. Секреты,
   телефоны и токены в протокол не включайте.

### 5.2 Сначала изолированный тест администратора

При работающем агенте один из двух администраторов пишет ему в личный чат:

```text
/диалог_тест
```

Ответит, что создан новый тестовый диалог с чистой памятью. Далее отправляйте обычные
сообщения клиента: «Здравствуйте», «Расскажите о занятиях», «Мне нужен человек»,
«Удалите мои данные», «Нет». В этом режиме заявки, CRM и уведомления руководителям
отключены независимо от рабочего режима. Завершение:

```text
/конец_теста
```

Полезные команды администратора в личном чате:

| Команда | Назначение |
| --- | --- |
| `/помощь` или `/проверка` | Показать доступные безопасные команды. |
| `/тест GPT <текст>` | Получить короткий тест OpenAI в личном чате администратора. |
| `/панель` | Получить одноразовый код для локальной панели. |
| `покажи заявки` | Посмотреть последние заявки. |
| `останови приглашения` | Остановить очередь приглашений. |
| `/мой_id` | Показать ID отправителя для настройки `.env`. |

### 5.3 Пилот с реальными входящими диалогами

Только после успешного изолированного теста, письменного разрешения пилотной группы и
резервной возможности ответить человеком:

1. Сделайте резервную копию **при остановленном агенте**:

   ```powershell
   cd C:\Anastasiya-AI
   Compress-Archive -Path .env,resources\knowledge.json,config\approved_groups.json,data -DestinationPath ..\anastasiya-backup-before-pilot.zip
   ```

2. В `.env` измените только:

   ```dotenv
   SAFE_TEST_MODE=false
   CRM_ENABLED=false
   OUTREACH_ENABLED=false
   AUTO_DISCOVER_GROUPS=false
   AUTO_JOIN_ENABLED=false
   FAMILY_RADAR_ENABLED=false
   FAMILY_RADAR_OUTREACH_ENABLED=false
   ```

3. Снова выполните `python scripts\launch.py doctor`, затем перезапустите
   `python scripts\launch.py main listen`.
4. Участник **сам** начинает личный чат с аккаунтом агента. Агент сначала запрашивает
   согласие на обработку вопроса с помощью ИИ; тестируйте ответы «да» и «нет».
5. Проверяйте как минимум: прозрачность о том, что это ИИ; отказ от общения (`/стоп`);
   удаление (`/удалить`); запрос человека (`/менеджер`); корректность знаний; отсутствие
   обещаний брони/записи без подтверждения; устойчивость к повтору и неожиданной теме.
6. При любом нежелательном ответе сразу остановите процесс `Ctrl+C`, не включайте
   исходящие кампании и зафиксируйте сценарий. При необходимости переключите обратно
   `SAFE_TEST_MODE=true` до следующего старта.

Команда `/диалог_тест` остаётся предпочтительным способом регрессионной проверки после
каждой правки: она не загрязняет историю реальных клиентов.

## 6. Локальная панель администратора

Панель слушает только `127.0.0.1:8765`, то есть открывается **на том же компьютере**,
где работает агент. Она не опубликована в интернет.

1. Запустите её во втором терминале:

   ```powershell
   cd C:\Anastasiya-AI
   .\.venv\Scripts\Activate.ps1
   python scripts\launch.py admin_panel
   ```

2. В личном чате с работающим агентом отправьте `/панель`; получите одноразовый код на
   5 минут.
3. На этом же компьютере откройте `http://127.0.0.1:8765` и войдите кодом.

В панели можно просматривать параметры, тестировать составленный запрос и ответ LLM,
настраивать разрешённые параметры общения, смотреть заявки, ставить контакт на стоп и
передавать его сотруднику. Панель не показывает ключи и сессии. Не пробрасывайте порт
8765 наружу через публичный туннель без отдельной аутентификации и проверки безопасности.

## 7. CRM, группы и исходящие действия

Включайте каждый внешний контур отдельно, после успешного пилота, и повторяйте
регрессионную проверку после каждого включения.

### CRM

Для AlfaCRM заполните в `.env` значения своего филиала (`ALFACRM_ALEX_*` и/или
`ALFACRM_YARO_*`), в том числе HTTPS URL, e-mail, API key, числовой branch и lead source.
Сначала используйте тестовый аккаунт CRM и один вымышленный лид. Затем включите:

```dotenv
CRM_ENABLED=true
```

Перезапустите агента и сверяйте карточку в CRM вручную. Код пытается избежать дублей по
телефону и создаёт лид, а не подтверждённую запись на занятие. Сбой поиска/создания CRM
должен считаться блокером, а не поводом повторно отправлять заявку наугад.

### Группы и рассылки

Значения `OUTREACH_ENABLED`, `AUTO_DISCOVER_GROUPS`, `AUTO_JOIN_ENABLED` и
`FAMILY_RADAR_OUTREACH_ENABLED` по умолчанию выключены намеренно. Их включение не
требуется для обычного входящего консультанта. Если бизнес-процесс законно требует
исходящее приглашение, используйте только документированное согласие получателя,
явное предпросмотр/подтверждение администратором и малые лимиты. Не включайте их
одновременно с первым реальным пилотом.

Для ответа в группе нужна запись в `config/approved_groups.json` с `admin_permission:
true`, `chat` и `marker`; без разрешения администратора группы запись добавлять нельзя.
Групповой ответ не должен содержать содержимое сообщений участников в сторонних системах.

## 8. Приёмка перед production

В архиве `tests/release_matrix.json` находятся 100 сценариев, а
`docs/reference/VOLUNTEER_QA.md` описывает порядок добровольной приёмки. Файл
`docs/reference/release_evidence.json` в поставке содержит только:

```json
{"automated_tests":"passed", "integration":{}, "cases":{}}
```

Поэтому `release_gate` **сейчас должен завершаться с блокерами**: доказательства реальных
интеграций и оценки сценариев отсутствуют. Это корректное поведение, не ошибка, которую
нужно обходить.

Перед production необходимо:

1. Выполнить `python scripts/run_tests.py` на финальной версии и сохранить вывод.
2. Провести приёмку 3–5 добровольцами на выделенном тестовом транспорте: покрыть все
   100 сценариев и минимум 20 проверить независимо двумя людьми.
3. Для каждого кейса заполнить в `release_evidence.json` все 7 `critical` значений
   `true`, девять оценок `scores` от 4 до 5 и обезличенную ссылку `evidence`.
4. Заполнить `integration` статусом `passed` для: `telegram_authorization`,
   `telegram_reconnect`, `openai_live`, `crm_reconciliation`, `clean_windows_install`,
   `existing_install_upgrade`, `shutdown_recovery`, `volunteer_review`.
5. Запустить gate:

   ```powershell
   cd C:\Anastasiya-AI
   .\.venv\Scripts\Activate.ps1
   python scripts\launch.py release_gate docs\reference\release_evidence.json
   ```

Готовность означает JSON с `"release_ready": true` и код завершения 0. Нельзя
подменять отсутствующие проверки `passed` или переносить доказательства с другой версии.

## 9. Формирование production-версии и работа с ней

### 9.1 Собрать неизменяемую поставку

1. Зафиксируйте проверенный commit/тег в Git и сохраните SHA-256 архива исходников.
2. Создайте новую чистую папку релиза; не накладывайте Python-файлы поверх старой версии.
3. Включайте в поставку исходники, `requirements*.txt`, `resources/`, `config/`,
   `docs/reference/`, тесты и этот guide. Исключите `.env`, `data/`, `*.session`, логи и
   резервные копии.
4. На целевой машине создайте venv и поставьте зависимости ровно по разделу 2, затем
   скопируйте `.env` из защищённого хранилища и выполните `doctor`, тесты и release gate.

### 9.2 Перенос с существующей установки

1. Остановите старый процесс.
2. Сделайте резервную копию старых `.env`, `data/`, собственного `resources/knowledge.json`,
   `config/approved_groups.json` и изменённого `resources/sales_expertise.md`.
3. Распакуйте новый релиз **в отдельную папку**.
4. Перенесите только перечисленные рабочие данные в соответствующие места новой папки.
5. Создайте/обновите venv новой папки, выполните `doctor`, `run_tests.py`, стартуйте в
   `SAFE_TEST_MODE=true` и пройдите короткий `/диалог_тест`.
6. Лишь затем возвращайте рабочий режим и наблюдайте пилотную группу.

### 9.3 Постоянная работа

Для запуска вручную после принятия релиза:

```powershell
cd C:\Anastasiya-AI
.\.venv\Scripts\Activate.ps1
python scripts\launch.py main listen
```

Оператор ежедневно контролирует, что процесс запущен, проверяет `/статус` из
администраторского чата, просматривает журнал терминала и локальные заявки, а также
реагирует на запросы `/менеджер`, `/стоп` и `/удалить`. До включения CRM заявки должны
обрабатываться человеком. Регулярно делайте резервные копии `data/` и `.env` в закрытое
хранилище с ограниченным доступом; перед бэкапом останавливайте агент.

На Linux для постоянной работы создайте сервис systemd от выделенного непривилегированного
пользователя (не root). Пример `/etc/systemd/system/anastasiya.service`:

```ini
[Unit]
Description=Anastasiya Telegram agent
After=network-online.target

[Service]
Type=simple
User=anastasiya
WorkingDirectory=/opt/Anastasiya-AI
ExecStart=/opt/Anastasiya-AI/.venv/bin/python scripts/launch.py main listen
Restart=on-failure
RestartSec=10
Environment=PYTHONUTF8=1

[Install]
WantedBy=multi-user.target
```

После создания файла администратор сервера выполняет:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now anastasiya
sudo systemctl status anastasiya
sudo journalctl -u anastasiya -f
```

Права на `/opt/Anastasiya-AI/.env`, `data/` и сессии должны быть только у пользователя
`anastasiya` (например, `chmod 600 .env` и `chmod 700 data`). Не публикуйте панель и не
открывайте входящие порты: агент сам устанавливает исходящие подключения к Telegram и
OpenAI.

## 10. Быстрая диагностика

| Симптом | Действие |
| --- | --- |
| `TG_API_ID`/`TG_API_HASH` не указаны | Проверьте `.env`, затем `python scripts/launch.py doctor`. |
| Команды администратора недоступны | Убедитесь, что два различных числовых ID внесены в `.env`; перезапустите агент. |
| Агент не отвечает реальному пилоту | Проверьте, не остался ли `SAFE_TEST_MODE=true`; для изолированной проверки используйте `/диалог_тест`. |
| Пилот не должен получать новые ответы | Нажмите `Ctrl+C`; при следующем запуске установите `SAFE_TEST_MODE=true`. |
| Панель не открывается с другого устройства | Это ожидаемо: она привязана к `127.0.0.1`. |
| `release_gate` не проходит | Откройте список `blockers`, заполните реальные доказательства, не редактируйте статусы фиктивно. |
