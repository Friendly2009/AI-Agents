# Анастасия

AI-агент для Telegram. Эта сборка упорядочивает содержимое предоставленного
`ANASTASIA_4_20.rar`: внутри исходного архива находились код и документы вплоть
до 4.26 RC1. Номер версии и готовность к эксплуатации этим изменением не повышаются.

## Обновление установленной службы Windows

Закройте старое окно Анастасии и откройте `Anastasiya-AI.exe` из распакованного архива. Приложение переключит работающую службу на новую версию с текущим профилем. После подключения строка состояния покажет «Чат 2». Администратор может проверить версию в Telegram командой `/версия`.

## Запуск в Windows

1. Распакуйте архив целиком в отдельную папку. Нужен Python 3.11 или новее.
2. Запустите `install_dependencies.cmd`.
3. Запустите `setup_settings.cmd` и заполните `.env`.
4. Выполните `check_readiness.cmd` для проверки настроек.
5. Запустите `start.cmd`. Для панели управления используйте `start_panel.cmd`.

По умолчанию сохранён безопасный режим из `.env.example`.
`reset_history.cmd` сбрасывает историю исходящих контактов; это не команда запуска.

## Переписка

Администратору достаточно написать обычное сообщение в личном чате или в Избранном сервисного аккаунта. Команда `/диалог_тест` открывает отдельную проверку клиентского сценария. Для ответов реальным клиентам нужен рабочий режим (`SAFE_TEST_MODE=false`), для свободных ответов модели — настроенный `OPENAI_API_KEY`.

## Где что лежит

| Папка | Содержимое |
| --- | --- |
| `src/` | Исходный код приложения |
| `scripts/` | Запуск команд и изолированный запуск тестов |
| `tests/` | Действующие регрессионные тесты и сценарии |
| `config/` | Список разрешённых групп `approved_groups.json` |
| `resources/` | База знаний `knowledge.json` и инструкция `sales_expertise.md` |
| `docs/reference/` | Критерии проверки, перечень настроек и сведения о проверках релиза |
| `reports/` | Результат проверки этой сборки |
| `data/` | Рабочие базы и сессии; создаётся при работе |

Старые инструкции и отчёты вынесены в отдельный архив истории. Их команды
относятся к прежней структуре. Старые номера в именах тестов обозначают
происхождение проверок: сами проверки сохранены и выполняются.

## Команды для разработки

Из корня проекта:

```powershell
python -m pip install -r requirements-dev.txt
python scripts/run_tests.py
python scripts/launch.py doctor
python scripts/launch.py evaluate_dialogues
python scripts/launch.py release_gate docs/reference/release_evidence.json
```

Для прежней команды `python main.py <аргументы>` теперь используйте
`python scripts/launch.py main <аргументы>`.
Тестовый запуск копирует код во временную папку, исключает рабочие `.env`,
базы и сессии, очищает настройки подключений и блокирует сеть.

## Перенос существующей установки

Остановите приложение и сохраните резервную копию прежней папки.
Распакуйте новую сборку отдельно. Перенесите `.env` и `data/` в корень новой
папки, свою `knowledge.json` — в `resources/`, а `approved_groups.json` —
в `config/`. Если меняли `sales_expertise.md`, перенесите его в `resources/`.
Не накладывайте новую структуру поверх старых файлов Python.

Автоматические проверки не подтверждают работу реальных подключений к Telegram,
OpenAI и CRM. Проверки внешних интеграций и ручная оценка диалогов остаются отдельным
этапом; подробности — в `docs/reference/release_evidence.json`.
